# Orchestration

协调布局计划、Desktop Surface、Renderer Provider/Session 和故障恢复。`IRendererProvider.CreateAsync` 只有在 Host 完成进程启动、Hello 认证、Initialize/Initialized 后才能返回。首次应用的固定顺序是：创建隐藏 provisional Surface，Attach 后等待 `SurfaceAttached`，Load 后等待 `ContentLoaded` 与 `FirstFramePresented`，回投 HostCommandLoop，再由单写者调用 `ReplaceSurfacesAsync` 并提交状态。恢复路径在新 Surface 上等待新的 `SurfaceAttached` 与 `FirstFramePresented`。

当前实现已按上述顺序显式替换 Surface；Explorer 恢复正向重附着、P1.7 首次/替换/退休故障和局部恢复失败整批重建均已完成自动验证及代表性人工验收。Renderer 内部使用 DComp 不改变现有 `AttachSurface`，除非跨进程开始传递 HWND 之外的 GPU 资源。Host 已实现正式 v1 进程 Provider、一次性认证、`Initialize/Initialized`、命令/事件映射、单接收泵、阶段状态机与超时；每个 Apply generation 发布不可变时间线和 `Succeeded / Failed / Cancelled / CircuitBroken` 终态，deadline 在终态释放，长期 Session 使用独立 retirement budget/result。P1.6 双屏长驻、10 次 process-cold 与 20 轮连续替换以及 P1.8 当前负坐标双屏断开/重连已经通过；历史固定 15 秒样本继续保留。恢复失败时仍不向旧 previous Surface HWND 发送 Attach：协调器终止状态不确定的 Renderer，仅遗忘 stale generation Surface 记录；Host 保留 Assignment，以 350 ms、1 s、2 s 三次预算执行全新会话重建，最终 generation 以 `CircuitBroken` 失败关闭。详细边界与状态见 `docs/renderer-protocol.md`、`docs/windows-desktop-host.md` 和 `docs/implementation-status.md`。

P1.6 诊断循环复用同一个 `HostCommandLoop`，但每轮创建全新的 Apply generation、Renderer 和 provisional Surface；下一 generation 原子提交后会显式等待上一 Session 的 retirement，再开始下一轮，最终 Shutdown 后聚合全部 Renderer 的 graceful/cleanup 结果。该能力只用于可靠性验收，不修改 Renderer Protocol v1、Application 端口或生产 allowlist。

P1.8 的 `DisplayReconciliationPlanner` 与 `DisplayTopologyChangedCommand` 单写者状态机已经接线：Assignment 是持久意图，离线显示器不会导致 Assignment 被删除；新显示器没有显式 Assignment 时不自动继承内容。bounds/DPI 或 Span 成员变化会重建，单独的 primary 标记/刷新率变化不会重建 HWND，稳定零显示器进入 Suspend。负坐标显示器拔插或主屏切换若改变 Progman 的虚拟桌面原点，会整批重建仍连接的 child Surface。对同一 DisplayId/壁纸/FitMode 的几何变化，新 provisional 批次准备前会先用 v1 `SetBounds` 和 `IDesktopHost.ResizeSurfaceAsync` 适配旧 Renderer 的既有已呈现帧与活动 Host Surface；正式 provisional 创建/Replace 仍执行完整结构和坐标门禁。每个 topology revision 提供独立可等待终态，更高 revision 会立即取消旧 preparation 和 retry。真实 churn、主屏切换、DPI/bounds+scale、位置/原点、旋转以及 Span position/scale/成员变化和 `PerDisplay→Span` 均通过；TG0 按 ADR-009 关闭且不进入 TG1。P1.8 已按 pure bounds/物理零显示器条件性 inconclusive、自动门禁通过的既定边界关闭；P1.9.0 Host 生命周期骨架和 P1.9.1 `TaskbarCreated` 正式事件链门禁均已关闭，下一阶段为 P1.9.2 系统锁定/电源状态。

P1.9.2 的系统状态命令按单调 revision 去重；Host 快照保留当前完整状态和 reason。系统非活动状态会重新应用到现有 Session，也会在新的 Apply、Display Reconciliation、Explorer Reattach/Rebuild 提交后再次应用，避免“锁屏期间准备、首帧后误恢复 Playing”。解锁/唤醒的 requested revision 只记录门禁状态，不重复向 Renderer 发送 Suspended；环境验证后的新 revision 才恢复 Playing。代码与自动门禁完成，实机验收后进入 P1.9.3。
