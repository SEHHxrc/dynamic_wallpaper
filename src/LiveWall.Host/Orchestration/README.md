# Orchestration

协调布局计划、Desktop Surface、Renderer Provider/Session 和故障恢复。`IRendererProvider.CreateAsync` 只有在 Host 完成进程启动、Hello 认证、Initialize/Initialized 后才能返回。首次应用的固定顺序是：创建隐藏 provisional Surface，Attach 后等待 `SurfaceAttached`，Load 后等待 `ContentLoaded` 与 `FirstFramePresented`，回投 HostCommandLoop，再由单写者调用 `ReplaceSurfacesAsync` 并提交状态。恢复路径在新 Surface 上等待新的 `SurfaceAttached` 与 `FirstFramePresented`。

当前实现已按上述顺序显式替换 Surface；Explorer 恢复正向路径会重建 Surface、在同一 Renderer 上重新 Attach 并等待第二次首帧，尽量保持播放位置，不把旧 HWND 直接换父级。独立 Renderer-child 跨 Shell generation 的功能恢复和清理已通过自动与人工验收；短暂 Shell 黑屏仍不等于产品级无缝恢复。Renderer 内部使用 DComp 不改变现有 `AttachSurface`，除非跨进程开始传递 HWND 之外的 GPU 资源。Host 已实现正式 v1 进程 Provider、一次性认证、`Initialize/Initialized`、命令/事件映射、单接收泵、阶段状态机与超时；每个 Apply generation 发布不可变时间线和 `Succeeded / Failed / Cancelled / CircuitBroken` 终态，deadline 在终态释放，长期 Session 使用独立 retirement budget/result。P1.6 双屏长驻、10 次 process-cold 与 20 轮连续替换已经通过；历史固定 15 秒样本保留但不再是待复现门禁。下一步以诊断专用测试 Renderer 故障计划验证双屏首次零提交、旧会话保持、退休异常隔离和 Explorer generation 整批恢复。恢复失败时仍不向旧 previous Surface HWND 发送 Attach：协调器终止状态不确定的 Renderer，仅遗忘 stale generation Surface 记录；Host 保留 Assignment，以 350 ms、1 s、2 s 三次预算执行全新会话重建，最终 generation 以 `CircuitBroken` 失败关闭。详细边界与状态见 `docs/renderer-protocol.md`、`docs/windows-desktop-host.md` 和 `docs/implementation-status.md`。

P1.6 诊断循环复用同一个 `HostCommandLoop`，但每轮创建全新的 Apply generation、Renderer 和 provisional Surface；下一 generation 原子提交后会显式等待上一 Session 的 retirement，再开始下一轮，最终 Shutdown 后聚合全部 Renderer 的 graceful/cleanup 结果。该能力只用于可靠性验收，不修改 Renderer Protocol v1、Application 端口或生产 allowlist。
